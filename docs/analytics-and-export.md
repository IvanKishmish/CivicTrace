# Аналітика й експорт відкритих даних

Два публічні ендпоїнти (без авторизації), що працюють поверх даних у базі. Реєстрація в `Program.cs` не потрібна: контролери, валідатори й обробники підхоплюються автоматично.

## 1. Аналітика `GET /api/v1/analytics?groupBy=…`

`groupBy`: `buyer` (за замовчуванням), `cpv`, `year`, `method`, `status`, `funding` (джерело фінансування), `expenditure` (код видатків). Інше значення — 400.

Відповідь:

```json
{
  "groupBy": "buyer",
  "summary": { "...": "показники по всіх закупівлях, key = \"all\"" },
  "groups": [ { "key": "21049708", "label": "ПОЛТАВСЬКА РАЙОННА РАДА", "...": "..." } ],
  "notes": [ "тексти для підпису під графіками" ]
}
```

Показники групи:

| Поле | Значення |
|---|---|
| `procurementsCount` | кількість закупівель |
| `contractSignedCount`, `notHeldCount` | за статусом |
| `noElectronicSystemCount` | закупівлі, проведені без електронної системи (спосіб проведення, не висновок) |
| `bidsListCompleteCount` | скільки закупівель мають повний реєстр пропозицій |
| `averageBidsInCompleteLists` | середня кількість пропозицій лише для них; `null`, якщо таких немає |
| `expectedAmount`, `contractAmount` | `{ withVat, withoutVat, vatUnspecified }`: суми окремо за позначкою ПДВ |
| `recordsWithMissingData`, `averageMissingDataItems` | скільки записів мають прогалини в даних і скільки в середньому |
| `recordsNeedingCheck` | скільки записів мають непідтверджені твердження |
| `fundingAmount` | сума фінансування за ключем групи (лише для `funding` і `expenditure`, у решті `null`) |

Групи відсортовано за кількістю закупівель (спадно), далі за ключем.

### Правила для інтерфейсу

1. Суми **не додавати** в одне число. Показувати три значення окремо або обрати одну позначку ПДВ і підписати її.
2. Ці показники не оцінюють закупівлі. Не використовувати слова «підозріло», «порушення», «ризик» і не підсвічувати кольором «погано».
3. «Без електронної системи» показувати як «спосіб проведення», з поясненням у підписі.
4. Показник `averageBidsInCompleteLists` підписувати: «Лише для закупівель із повним реєстром пропозицій (N із M)».
5. Тексти з `notes` вивести під відповідним блоком як є.
6. Показник повноти даних подавати як інформацію про дані, а не про замовника: «У N із M записів є прогалини в даних».

### Очікувані значення для сид-файлу (8 закупівель)

**Summary:** 8 закупівель; договір укладено 6, торги не відбулися 2; без електронної системи 4; повних реєстрів 2, середня кількість пропозицій 6.5 (8 і 5); очікувана сума: з ПДВ 3 895 226,34, без ПДВ 23 232,00, не вказано 0; сума договорів: з ПДВ 2 035 444,47, без ПДВ 0, не вказано 23 232,00; записів із прогалинами 8, у середньому 1.625 на запис; записів, що потребують перевірки, 2.

| groupBy | Групи (key → кількість) |
|---|---|
| `buyer` | `21049708` → 7 (договір укладено 5); `42277729` → 1 (договір укладено 1) |
| `cpv` | `09120000-6` → 2; `09310000-5` → 2; `65210000-8` → 2; `45000000-7` → 1; `72260000-5` → 1 |
| `year` | `2024` → 3; `2025` → 2; `2026` → 2; `2023` → 1 |
| `method` | `no_electronic_system` → 4; `request_for_quotations` → 2; `open_tenders_with_specifics` → 2 |
| `status` | `contract_signed` → 6; `not_held` → 2 |

Запит `?groupBy=foo` повертає 400.

**Фінансування (`groupBy=funding` / `expenditure`).** Дані беруться з планів закупівель. Закупівля, для якої план не прочитано, потрапляє в групу `unknown` («Джерело фінансування невідоме» / «Код видатків невідомий»). Закупівля з кількома рядками фінансування входить у кожну свою групу один раз; `fundingAmount` — сума за ключем. У сид-файлі всі 8 закупівель мають одне джерело фінансування, тому очікується: `funding` → одна група «Місцевий бюджет» (8 закупівель, `fundingAmount` 3 919 608,34); `expenditure` → «ТПКВКМБ 0150 – Організаційне, інформаційно-аналітичне та матеріально-технічне забезпечення діяльності обласної ради, районної ради, районної у місті ради (у разі її створення), міської, селищної, сільської рад» (3 закупівлі, 1 938 861,30), «ТПКВКМБ 1151 – Забезпечення діяльності інклюзивно-ресурсних центрів за рахунок коштів місцевого бюджету» (1 закупівля, 6 900,00) і `unknown` (4 закупівлі без коду, 1 973 847,04). Для закупівель, імпортованих з Prozorro API, числа залежатимуть від планів.

Якщо після імпорту з Prozorro API з'являться нові записи, ці числа зміняться.

## 2. Експорт `GET /api/v1/export/procurements?format=csv|json`

Повертає файл для завантаження з усіма закупівлями (без пагінації). Для великих обсягів потрібно додати фільтри або ліміти.

- `format=csv` (за замовчуванням): UTF-8 із BOM, роздільник кома, 35 колонок (ідентифікатори, замовник, виконавець, суми з позначками ПДВ, статуси, місце, координати зі статусом, періоди, кількість подій, пропозицій і прогалин, посилання на джерело). У Excel із українською локаллю краще відкривати через «Дані → З тексту/CSV» і вказати роздільник «кома». Текстові поля, що починаються з `=`, `+`, `-`, `@`, отримують префікс `'` (захист від формул).
- `format=json`: ті самі об'єкти, що й у `GET /api/v1/procurements`, масивом; кирилиця без екранування.
- Ім'я файлу: `civictrace-procurements-ГГГГММДД.csv|json`.
- Інший формат — 400.

Очікування для сид-файлу: CSV має 9 рядків (заголовок і 8 записів), JSON — масив із 8 об'єктів.

## 3. Перевірка в Scalar

| Запит | Очікування |
|---|---|
| `GET /analytics` | 200, `groupBy: "buyer"`, 2 групи |
| `GET /analytics?groupBy=cpv` | 5 груп |
| `GET /analytics?groupBy=year` | 4 групи, перша `2024` |
| `GET /analytics?groupBy=foo` | 400 |
| `GET /export/procurements` | завантажується CSV, відкривається в Excel без «кракозябрів» |
| `GET /export/procurements?format=json` | завантажується JSON із 8 записами |
| `GET /export/procurements?format=xml` | 400 |

Суму `contractAmount` у `summary` звірте вручну із SQL: `SELECT SUM("ContractAmount") FROM "Procurements"` має дорівнювати сумі трьох полів `contractAmount` у `summary`.

## 4. Що це дає для хакатону

- Показник «скільки закупівель без електронної системи», «скільки записів із прогалинами в даних» і «середня кількість пропозицій» працюють без жодних висновків про вину, тобто відповідають принципу проєкту й темі прозорості.
- Відкритий експорт даних збігається з темою хакатону (відкриті дані): набір можна завантажити й використати поза сервісом.
- Фронтенд-задача: сторінка «Аналітика» з вибором `groupBy`, підсумковими картками з `summary` і діаграмою за `groups` (приклад — кількість закупівель за замовником чи ДК-кодом).
