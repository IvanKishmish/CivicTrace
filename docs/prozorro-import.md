# Імпорт закупівлі з Prozorro API

Мета: ввести внутрішній ідентифікатор закупівлі (`apiId`, 32 hex-символи) і отримати в базі картку, зібрану з офіційного публічного API Prozorro, без ручного копіювання зі сторінки.

> **Статус: код написано за документацією API, живого запиту до Prozorro я не робив.** У середовищі, де я писав код, немає доступу до мережі. Імена полів взято з prozorro-api-docs.readthedocs.io. Перший крок — перевірити їх на справжніх відповідях (див. «Перший запуск»).

## Як це працює

1. `POST /api/v1/import/procurements` (роль Editor або Admin).
2. Клієнт запитує `GET https://public-api.prozorro.gov.ua/api/2.5/tenders/{apiId}`. Відповідь обгорнута в `{ "data": { ... } }`.
3. `ProzorroTenderMapper` перетворює відповідь на наші поняття: чисте перетворення без звернень до бази. Те, чого немає у відповіді, потрапляє в `missingData`/`needsCheck`, а не вигадується.
4. Обробник знаходить або створює організації за ЄДРПОУ, збирає `Procurement` з подіями, пропозиціями, примітками та прогалинами. Для реального імпорту зберігає в базу.

Запит:

```json
{ "apiId": "33c8473878374484a3fde02450ac73b9", "dryRun": true, "replaceExisting": false }
```

- `dryRun` (за замовчуванням `true`): нічого не пише в базу, показує, що було б збережено.
- `replaceExisting`: якщо закупівля з таким `ExternalId` уже є, видалити її й імпортувати заново. Без цього реальний імпорт існуючої закупівлі повертає 409.

Відповідь: `{ saved, alreadyExisted, warnings[], procurement }`, де `procurement` має ту саму форму, що й `GET /procurements/{id}`.

## Відповідність полів

| Наше поле | Звідки в API | Примітка |
|---|---|---|
| `externalId` | `tenderID` | UA-РРРР-ММ-ДД-NNNNNN-a |
| `apiId` | `id` | |
| `title` | `title` | |
| `kind` | `mainProcurementCategory` | `goods`, `services`, `works`; інше значення — помилка |
| `cpv` | перший `items[].classification` зі схемою ДК021 або CPV | |
| `method` | `procurementMethodType` | див. «Типи процедур» |
| `status` | `status` | `complete` → договір укладено, `unsuccessful` → торги не відбулися; інші статуси поки не підтримуються |
| `sourceStatus` | `status` | `complete` → «Завершена», `unsuccessful` → «Торги не відбулися» |
| замовник | `procuringEntity` (`identifier.id`, `identifier.legalName` або `name`, `address`) | потрібна схема `UA-EDR` |
| переможець | `suppliers[0]` єдиної `awards[]` зі статусом `active` | кілька активних award (багатолотові закупівлі) поки не підтримуються |
| сума договору | `contracts[]` зі статусом `active` → `value` | якщо немає, береться `award.value` з позначкою в `needsCheck` |
| очікувана сума | `value` | разом із `valueAddedTaxIncluded` |
| місце | `items[].deliveryAddress` | формат «індекс, країна, область, населений пункт, вулиця»; тип `work` для робіт і ДК 45…, інакше `delivery` |
| координати | `items[].deliveryLocation`, якщо є | завжди `needs_check` |
| період | `items[].deliveryDate` | |
| підстава неконкурентної закупівлі | `causeDetails.title` і `causeDetails.description` (лише для `reporting`) | якщо немає, потрапляє в `missingData` |
| пропозиції | `reporting`: лише переможець; конкурентні: `bids[]`, якщо є, інакше учасники з `awards[]` | `bidsListComplete = true`, лише якщо є ≥ 2 пропозиції з `bids[]` |
| події | `tenderPeriod`, `enquiryPeriod`, `awards[].date`, `contracts[].dateSigned` | дата підписання договору тепер заповнюється, якщо API її повертає |

Не імпортується: контактні особи, документи, фінансування й ідентифікатор плану (їх немає у відповіді тендера; про це є запис у `missingData`).

## Типи процедур

Відомі з документації й вже закладені: `reporting` → «Закупівля без використання електронної системи», `aboveThresholdUA.defense` → «Відкриті торги з особливостями».

Для «Запит (ціни) пропозицій» тип процедури заздалегідь невідомий (це може бути `priceQuotation`, `belowThreshold` або інший). Не вгадуємо: імпорт повертає помилку `Prozorro.UnsupportedMethod` із назвою справжнього типу. Додайте його в конфігурацію (наприклад, у `appsettings.Development.json`):

```json
"Prozorro": {
  "MethodTypeMap": {
    "<тип з помилки>": "RequestForQuotations"
  }
}
```

## Перший запуск

1. Перед запитом через API перевірте відповідь Prozorro вручну (у браузері або `curl`):
   `https://public-api.prozorro.gov.ua/api/2.5/tenders/33c8473878374484a3fde02450ac73b9`
   Подивіться: чи є `data.tenderID`, `procurementMethodType`, `mainProcurementCategory`, `causeDetails`, `awards[].suppliers[].identifier`, `contracts[].value`, `items[].deliveryAddress`.
2. Запустіть імпорт у режимі `dryRun: true` для кожного з восьми apiId нижче й порівняйте з сид-файлом.
3. Для двох закупівель «Запит (ціни) пропозицій» додайте відповідність типу (див. вище), якщо імпорт повернув `UnsupportedMethod`.
4. Реальний імпорт у **окрему тестову закупівлю** (яких немає в сид-файлі), щоб не плутати дані.

## Що має збігатися із сид-файлом, а що ні

**Має збігатися:** `id`, `title`, `kind`, `cpvCode`, `cpvName`, `buyer`/`buyerEdrpou`, `contractor`/`contractorEdrpou`, `expectedAmount` і `contractAmount` разом із ПДВ-позначками, `status`, `sourceStatus`, `periodStart`/`periodEnd`, кількість і суми `bids`, `nonCompetitiveBasis` для `reporting`.

**Може відрізнятися (не помилка):**
- `events`: API дає точніші дати, зокрема дату підписання договору; немає подій «протокол опубліковано» та «звіт» (їх немає в тендері як окремих полів);
- `funding`, `planId` порожні (є запис у `missingData`);
- `buyerAddress`, `address`: формат може відрізнятися від того, що я нормалізував у сид-файлі;
- `verifiedAt`/`verifiedBy` порожні; `notes` має запис «Імпортовано з Prozorro API».

Усі розбіжності у **суттєвих** полях (назва, сума, ЄДРПОУ, статус) — це або помилка мапінгу, або помилка в сид-файлі: розберіться в кожному випадку.

## Обмеження (свідомі)

- Підтримуються лише статуси `complete` і `unsuccessful`. Закупівлі в процесі або скасовані повертають зрозумілу помилку; для цього потрібні нові статуси в домені.
- Лише закупівлі з одним активним award (без багатолотових).
- Переможець лише юридична особа з 8-значним ЄДРПОУ; фізичні особи свідомо не зберігаються (імпорт повертає помилку).
- Пошуку за `UA-...` немає: потрібен `apiId` (його видно на сторінці закупівлі поруч із `UA-...`).
- Помилки зв'язку з Prozorro повертаються як 500 із зрозумілим текстом (код помилки `Prozorro.*`); для точнішого 502 треба доопрацювати `ApiController`.
- API публічний, обмежень на одиничні запити документація не називає; ендпоїнт імпорту обмежений ролями й лімітом запитів.

## Умови використання

Дані Prozorro відкриті. У кожного запису зберігається `sourceUrl` на сторінку закупівлі; його треба залишати видимим у інтерфейсі.
