# Схема сид-файлу `data/samples/procurements.seed.json`

Файл — JSON-масив із 8 записів. Дані зібрано зі сторінок prozorro.gov.ua (скріншоти й текст від 30–31.10.2026). `null` означає «немає / на сторінці не вказано». Порожній масив — «елементів немає».

Файл не редагується фронтендерами. Зміни структури робить тімлід і оновлює цей документ.

## Ідентифікація

| Поле | Тип | Опис |
|---|---|---|
| `id` | рядок | Ідентифікатор закупівлі (`UA-РРРР-ММ-ДД-NNNNNN-a`). Ключ у посиланні на картку |
| `apiId` | рядок (32 hex) | Внутрішній ідентифікатор зі сторінки закупівлі, показаний поруч із `id`. Ймовірно, ключ для запитів до API; **перевірити першим запитом** (задача M1-3) |
| `planId` | рядок / `null` | Ідентифікатор плану закупівлі, якщо сторінка його показує |
| `title` | рядок | Назва закупівлі як на сторінці |
| `kind` | рядок | `Товари` / `Послуги` / `Роботи` — «Вид предмету закупівлі» зі сторінки. Для ремонту/будівництва орієнтуйтесь на `cpvCode`, що починається з `45` |
| `cpvCode`, `cpvName` | рядки | Код і назва за ДК 021:2015 |
| `procurementType` | рядок | Спосіб закупівлі як у джерелі |
| `sourceUrl` | рядок | Посилання на закупівлю в Prozorro |

## Сторони

| Поле | Тип | Опис |
|---|---|---|
| `buyer`, `buyerEdrpou`, `buyerAddress` | рядки | Замовник, код ЄДРПОУ, місцезнаходження з сторінки |
| `contractor`, `contractorEdrpou` | рядок / `null` | Переможець/виконавець; `null`, якщо договору немає |

Контактні особи замовника в набір **не** включено. Також у набір не включаємо ідентифікаційні номери фізичних осіб.

## Гроші

| Поле | Тип | Опис |
|---|---|---|
| `expectedAmount` | число / `null` | Очікувана вартість |
| `contractAmount` | число / `null` | Вартість договору |
| `currency` | рядок | `UAH` |
| `expectedVatIncluded`, `contractVatIncluded` | `true` / `false` / `null` | Чи включає сума ПДВ за позначкою на сторінці; `null` — не вказано |
| `funding` | масив | Джерела фінансування, див. нижче |

Суми не додаємо й не порівнюємо між собою без окремого підтвердження.

### `funding[]`

`source` (напр., «Місцевий бюджет»), `expenditureCode` (код класифікації видатків або `null`), `territory` (адміністративно-територіальна класифікація або `null`), `amount` (число).

## Статус

| Поле | Значення |
|---|---|
| `status` | `contract_signed` або `not_held` |
| `statusLabel` | «Договір укладено» або «Торги не відбулися» |
| `sourceStatus` | Статус у Prozorro «як є» («Завершена» / «Торги не відбулися») |
| `executionStatus` | `not_confirmed` (договір укладено, виконання не підтверджено) або `not_applicable` (договору немає) |

`sourceStatus` «Завершена» у Prozorro позначає завершену процедуру закупівлі. Це не означає, що роботи чи постачання виконано.

## Місце

| Поле | Значення |
|---|---|
| `address` | Адреса з сторінки закупівлі («Місце поставки») або `null` |
| `placeType` | `work` — місце робіт; `delivery` — «Місце поставки» зі сторінки закупівлі; `unknown` — на сторінці не вказано |
| `latitude`, `longitude` | Числа або `null` |
| `hasCoordinates` | `true`, якщо координати є |
| `coordinatesStatus` | `needs_check` або `null` |

Координат на сторінках Prozorro немає: наявні координати отримані додатково й **не звірені**. Адреси «Шевченка, 5» і «Шевченка, 5Г» у наборі мають однакову точку; чи це одна будівля, не підтверджено.

## Період

`periodStart`, `periodEnd` — рядки `РРРР-ММ-ДД` або `null`. Це «Дата поставки» зі сторінки закупівлі (період поставки або виконання). Для закупівель без поставки (торги не відбулися) — `null`.

## Підстава неконкурентної закупівлі

`nonCompetitiveBasis`: об’єкт `{legalBasis, justification, sourceUrl}` або `null`. Заповнений там, де сторінка показує блок «Обґрунтування проведення неконкурентної закупівлі». Якщо закупівля без електронної системи, а блоку немає, у `missingData` є відповідний запис.

## Пропозиції

| Поле | Опис |
|---|---|
| `bidsListComplete` | `true` лише якщо сторінка показує повний реєстр пропозицій (запит цін пропозицій) |
| `bids[]` | `bidder`, `bidderEdrpou`, `amount`, `vatIncluded`, `outcome` (`winner`, `rejected` або `null`) |

Для закупівель без реєстру `bids` містить лише переможця із протоколу; кількість пропозицій у такому разі не показувати.

## Події (`events`)

Кожна подія: `date` (`РРРР-ММ-ДД` або `null`), `stage`, `title`, `dateNote` (пояснення до дати або `null`), `sourceUrl`.

Якщо `date` дорівнює `null`, подія стоїть в масиві на своєму місці, а на екрані має підпис «Дату не вказано» й `dateNote`. Сортування — за датою, при рівних датах і для `null` — за порядком у масиві.

| `stage` | Що означає |
|---|---|
| `announced` | Оголошення закупівлі |
| `protocol_published` | Опубліковано електронний протокол рішення про проведення закупівлі |
| `clarification_deadline` | Кінцевий строк звернень за роз’ясненнями та оскарження умов |
| `bids_deadline` | Кінцевий строк подання пропозицій |
| `bids_opened` | Розкриття пропозицій |
| `bid_rejected` | Пропозицію відхилено |
| `award_notice` | Повідомлення про намір укласти договір |
| `reported` | Опубліковано протокол розкриття пропозицій / звіт |
| `contract_signed` | Укладено договір |
| `cancelled` | Закупівлю відмінено |

Дати подій `bid_rejected` і `award_notice` — це дата публікації протоколу; точної дати повідомлень сторінка не показує (так і написано в `dateNote`). Дату підписання договору сторінка закупівлі не показує, вона є на сторінці договору.

## Тексти для користувача

| Поле | Тип | Правило |
|---|---|---|
| `notes` | `{text, sourceUrl}[]` | Нейтральні факти з джерелом, без оцінок |
| `missingData` | рядки | Чого не знайдено в перевірених джерелах |
| `needsCheck` | рядки | Що на сторінці не уточнено й треба перевірити |

## Перевірка запису

`verifiedAt` — дата, коли команда відкривала сторінку (30–31.10.2026); `verifiedBy` — `null`, доки не вказано виконавця.

## Що змінилося відносно перших версій

- Видалено `category` → `kind`, `cpvCode`, `cpvName`; `missingDataNotice` → `notes`, `missingData`, `needsCheck`.
- `status` розділено на `status`, `statusLabel`, `sourceStatus`; додано `executionStatus`. Код `no_bids` перейменовано на `not_held`: сторінка не пише, що пропозицій не було, лише що торги не відбулися.
- Додано `apiId`, `planId`, `buyerAddress`, `funding`, `nonCompetitiveBasis`, `bids`, `bidsListComplete`.
- `startDate`/`endDate` → `periodStart`/`periodEnd`: це період поставки, а не дати процедури.
- Тексти про «монополіста» прибрано: на сторінці лише формулювання постанови (постачальник «останньої надії»).
- Адреса «Шевченка, 5/5Г» — це «Місце поставки», а не адреса замовника: замовник (Полтавська районна рада) зареєстрований у с. Супрунівка.
- Дати договорів, які на сторінках закупівлі не показано, замінено на `null`.
